# -L: コマンド付きで最初に起動してもコンテナが生き続けるようにする

## 目的

`dozo -L cmd` を繰り返して環境を積み上げる使い方（バッチ実行を含む）を、
最初の起動から可能にする。

現状は、コンテナがない状態で `dozo -L cmd` を実行すると `cmd` がコンテナの
主プロセスになり、終了するとコンテナも止まる。次の `dozo -L cmd2` では
`docker start` が `cmd` を再実行し、`cmd2` の exec は失敗するか偶然間に合う。
そのため、最初は引数なしの `dozo -L` でシェルを起動し、抜けてから
`dozo -L cmd` を積み上げる手順が必要になっている。

今回の変更では、この手順を自動化する。

## 目標 / 非目標

- 目標: コンテナがない状態での `dozo -L cmd` が、
  「シェルを主プロセスとしてコンテナを作る → そこに `cmd` を exec する」と
  動作すること。作られるコンテナは、引数なしの `dozo -L` で作ったものと同じ。
- 非目標: 作成後に `-V` / `-P` / `-O` などの作成時設定を変えること。
  これは既存の `dozo -K -L ...` による作り直しで対応する（中身はリセットされる）。
- 非目標: 引数なしで作成する場合、およびコンテナが既にある場合の動作の変更。

## 検討した方法

- A. 常に `sleep infinity` などの待機プロセスでコンテナを作り、すべて exec する。
  対話時の動作（シェルを抜けると止まる、attach）が変わるので不採用。
- B. コマンド付き作成時だけ待機プロセスで作り、ラベルで区別する。
  コンテナが 2 種類になり、場合分けが増えるので不採用。
- C. `docker commit` でイメージとして積み上げる。重く、目的に合わないので不採用。
- **採用: コマンド付き作成時は、イメージ既定のシェルを `docker run -d -i -t`
  で起動し、続けて `docker exec` でコマンドを実行する。**
  コンテナは 1 種類のままで、既存の start / attach / exec の処理がそのまま使える。

## 設計

- `-L` かつコンテナが存在せず、かつコマンド引数があるとき:
  1. 現在の `docker run` と同じオプションに `-d -i -t` を加え、コマンド引数を
     付けずに起動する（`--interactive` / `--tty` の重複は避ける）。
     `docker run -d` が標準出力に出すコンテナ ID は捨てる
     （標準出力はコマンドの出力のためにあける）。
  2. 続けて、既存の running 時の処理と同じ形で `docker exec` を実行し、
     その終了ステータスで終了する。
- 上記以外（引数なしでの作成、既存コンテナ）は現状どおり。
- `-A`（pull）、`-q`、dryrun（`-n`）は作成時に今と同じように効く。
  dryrun では `docker run -d ...` と `docker exec ...` の両方が表示される。
- POD の LIVE CONTAINER 節の「Container does not exist」の説明を更新する。

## 確認済みの事項

- docker 29.8.2 / alpine で、stdin が端末でなくても `docker run -d -i -t` は起動し、
  running のまま残る。exec で作ったファイルは、stop → start 後も残り、
  再起動後も running になる。

## 前提・制約

- イメージ既定のコマンドがシェルのように入力を待ち続けるものであること
  （`tecolicom/xlate` など、dozo が想定するイメージは該当する）。
  すぐ終了するコマンドが既定のイメージでは、exec が失敗する。
