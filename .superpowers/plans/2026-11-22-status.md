# --status (-S) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `dozo -S` shows what dozo would do here and why, lists dozo's live containers and derived images, and prints the commands to clean up, without changing anything.

**Architecture:** `-S` runs the normal option parsing, `.dozorc` reading, label lookup and `with_image -c`, then prints the status and exits just before the kill/live/run sections. Every `die` on that path that a status should report instead (several containers, other directory, unknown image for -KL) goes through one helper that records a note in status mode. The two lists come from one batched `docker inspect` of all containers and one of all derived images.

**Tech Stack:** Bash 4.4 (`script/dozo`), getoptlong.sh 1.1.0+, Perl Test::More with a docker stub.

**Spec:** `.superpowers/specs/2026-11-22-status-design.md` (read it, including "設計者の判断").

## Global Constraints

- `-S` never runs a docker command that changes anything: no `pull`, `build`, `rm`, `run`, `start`, `unpause`, `exec`, `attach`.
- Output on stdout; ordinary `warn` lines stay on stderr. Exit 0 when the status is shown; non-zero only when docker cannot be asked (`docker ps -a -q` fails), or when a command is given (`--status takes no command`).
- Bash and docker only (no perl at run time).
- Behaviour without `-S` unchanged; the whole existing suite (`prove -lr t`) stays green.
- The image of a status is "decided" exactly as a real `-L` would decide it, including "an image in .dozorc is a default" (commit 246c15a).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no `Claude-Session:` line. Do not commit Changes.

## Review Focus

- `dozo -KL -S` in a directory with a container: nothing is removed (no `rm` in the stub log), and the status says it would be.
- Several labeled containers for the directory (the user's real case: `xlate.` and `brew.ir_report_checklist`): `-S` exits 0 and lists both, where `dozo -L` would die.
- A stray word in `.dozorc`: the rest (later `.dozorc` files and the command line) is still the command, as before the per-file parse.
- An unknown feature in `--with` (or in a derived image's `dozo.with`): reported, not fatal.
- An empty Docker (no containers, no derived images): the lists say `none`, no cleanup section.

Tests (subtest `here`), each with HOME and cwd in a temp dir as `t/03_dozo.t` does, assertions on stdout:
- `dozo -S -I alpine` → exit 0; stdout matches `/^here: \Q$work\E$/m`, `/^  image +alpine \(command line\)$/m`, `/^  container +alpine\.proj, (none|create)/m`.
- `.dozorc` with `-D` in HOME, `dozo -S` → `/image +tecolicom\/xlate \(\Q$home\E\/\.dozorc\)/`.
- STUB_LABELED=`alpine.proj`, STUB_CONTAINER=1, `.dozorc` `-D` → `/container +alpine\.proj, running \(found by label\)/` and image line `/\(label of alpine\.proj\)/` or the `dozo.image` label value.
- STUB_LABELED=`alpine.proj debian.proj` → exit 0, `/several containers.*alpine\.proj.*debian\.proj/`.
- No image, no container → exit 0, `/no live container for .*-I/`.
- `-KL -S` with a found container → log has no `^rm ` line; stdout `/would remove alpine\.proj/` and `/then create from /`.
- `-A -S -I alpine` → log has no `^pull`; stdout `/-A.*would pull alpine/`.
- `--with hello -S -I alpine` (feature file present, stage missing) → log has no `^build`; stdout `/--with +hello: .*not built yet/`; unknown feature `--with nosuch -S -I alpine` → exit 0, `/nosuch.*not found/`.
- STUB_CONTAINER_MOUNT=`/other/proj` with `-S -I alpine` → exit 0, `/note +.*\/other\/proj/`.
- `dozo -S -I alpine echo hi` → non-zero, stderr `/--status takes no command/`.
- STUB_PS_FAILS=1 → non-zero.
- For every case above: the log never contains `^(pull|build|rm|run|start|unpause|exec|attach)\b` (check in the `$calls` helper).
- `.dozorc` stray word, unchanged by the per-file parse: rc in HOME `-I alpine foo` and rc in cwd `-E X`, `dozo bar` runs `run ... alpine foo -E X bar` (stub log; the rest after the word is the command).

- [ ] **Step 2: Run, expect failures** — `prove -l t/04_status.t` → FAIL (`-S` unknown option).

- [ ] **Step 3: Implement**
- OPTS: `[     status | S   # show the status, change nothing ]=`; SYNOPSIS line `    -S, --status       show live containers and derived images`.
- `.dozorc`: keep one flat `rc_opts`, plus `rc_files` and `rc_counts` arrays (file, number of words). Parse each file's slice separately, then the command line; `in_from` is the file path or `command line`; `image_set` sets `image_from=$in_from` and `image_given` is `[[ $image_from == "command line" ]]`. A leftover word after a slice ends parsing: the remaining slices and the command line are appended to the command, as before.
- `live_fail()`: `die` without `-S`; with `-S` append to `status_notes` and `return 1`. Use it for the three dies in the lookup block / `live_check_mount` (several containers, other directory, unknown image for `-KL`), and let callers continue on failure in status mode.
- With `-S`: `(( $# )) && die "--status takes no command"`; `command docker ps -a -q > /dev/null || die "cannot ask docker"`; set `live=1` before the lookup so here is seen as `-L`; after the lookup, call `status_main` and `exit 0` before "Kill container".
- `status_here` prints the lines in the spec's example: `here:`, `image`, `container`, `--with` (via `( with_image -c ... )` in a subshell; feature errors captured as text), `-A`, `-K`/`-KL` would-lines, then each `status_notes` as `  note       ...`. The existing warnings of the live block (image mismatch, `--with` mismatch, `-A`) are computed the same way and printed as notes.

Format of the one batched call, `command docker inspect --format "$fmt" $(ids)`, tab separated:

"DOZO_RUNNING_ON_DOCKER=1"}}dozo{{end}}{{end}}	{{range .Mounts}}{{if eq .Destination "/work"}}{{.Source}}{{end}}{{end}}`

### Task 3: derived images and the cleanup section

**Files:** Modify `script/dozo` (`status_images`, cleanup output in `status_main`), `t/04_status.t`.

**Interfaces:** Consumes `with_image -c`, `status_cleanup`. Calls: `command docker image ls --filter label=dozo.base --format '{{.Repository}}:{{.Tag}}\t{{.ID}}\t{{.CreatedSince}}'`, then one `command docker image inspect --format '{{index .Config.Labels "dozo.base"}}\t{{index .Config.Labels "dozo.with"}}' TAG...` (stub prints columns 4-5 of `$STUB_DERIVED` for each TAG, in the given order).

- [ ] **Step 1: Failing tests** (subtest `derived images`): first run `dozo -B -I alpine --with hello true` with the stub so the real tag of the current stage is in `STUB_IMAGES`; read it back. STUB_DERIVED lines:
  - that tag, base `alpine`, with `hello` → `current`, and `*` when `-S --with hello -I alpine` would use it.
  - `dozo/alpine:hello-1` base `alpine` with `hello` → `outdated`, cleanup `docker image rm dozo/alpine:hello-1`.
  - `dozo/alpine:gone-2` with `gone` (no feature file) → `feature gone`, cleaned up.
  - `dozo/nob:x-3` base `nob` (not in STUB_IMAGES) → `base gone`, cleaned up.
  - an outdated tag that is the `.Config.Image` of a container in STUB_CONTAINERS → not in the cleanup lines.
  Cleanup section: `/^to clean up:\n(  docker .*\n)+/m`; absent when there is nothing to clean. Empty STUB_DERIVED → `derived images:\n  none`.
- [ ] **Step 2: Run, expect FAIL.**
- [ ] **Step 3: Implement `status_images`** (each state computed in a subshell: `image=$base with_names=(split $with at ,) with_image -c` and compare its `run_image` with the tag; for a middle stage compare with the tag the chain prefix gives). Columns IMAGE BASE WITH STATE CREATED. Then `status_main` prints `to clean up:` with `status_cleanup` when not empty.
